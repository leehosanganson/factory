# PostgreSQL REST job store

`internal/restjobs.PostgresStore` is an opt-in package-level implementation of the full `restjobs.Store` contract. It persists admission, principal-scoped idempotency, issue provenance, status, bounded lifecycle history, cancellation, provider attempts/outcomes, verification evidence, and attempt ownership in one PostgreSQL schema. Admission and worker-capacity decisions are serialized across connections; attempt leases and validity use PostgreSQL's database clock. Running jobs whose lease expired or was interrupted remain `running` and require operator investigation; the store never automatically reclaims or replays them.

PostgreSQL is selectable by the REST server through strict server JSON using `persistence.backend: "postgres"` and `persistence.dsn`. Memory remains the default and SQLite behavior is preserved. The PostgreSQL database may be shared by a workers-disabled API control plane and separately launched `factory worker` processes. `limits.workers` is enforced as a database-wide execution cap across these processes; every config sharing the database must agree on the same value, including an API config with local workers enabled or disabled. The all-in-one server continues to run local workers by default; Factory does not provide a fleet coordinator. Memory and SQLite limits are process-local, and SQLite remains single-server storage. `FACTORY_TEST_POSTGRES_URL` enables the opt-in integration tests, which require PostgreSQL 18 and use temporary schemas. SQLite and PostgreSQL have independent embedded migration histories and are not interchangeable database files.

Configured PostgreSQL fails closed if unavailable, and migration readiness is established before the listener opens. Queued jobs are resumed by each runtime instance; interrupted running jobs are retained for operator handling and are not replayed. Authenticated disposition and read-only provider reconciliation capabilities work with the PostgreSQL store. The CLI backup and portable recovery-bundle commands remain SQLite-only and reject PostgreSQL configs; use PostgreSQL-native backup and restore procedures. See [REST server](rest-server.md), [server configuration](rest-server-config.md), and the [REST job contract](../roadmap/rest-api-contract.md) for current behavior and remaining product requirements.
