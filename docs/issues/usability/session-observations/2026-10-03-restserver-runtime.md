# REST server runtime implementation session

- **Scope:** Implemented the REST runtime composition and `factory server --config <absolute-path>` CLI on a fresh worktree initially based on freshly fetched `origin/main` (`77da73a`). PR #83 was open/unmerged at initial inspection and its combined-output fix was not present in that base. After the runtime was independent of that fix, PR #83 merged; the PR branch remains based on its original fresh base and uses APIs available there. The pre-existing roadmap edit in the original checkout was preserved and not copied into this isolated PR.
- **Results location decision:** No configurable `results_dir` was added. Runtime results default under `${XDG_STATE_HOME:-~/.local/state}/factory/rest-server`; repository aliases map to stable SHA-256-derived directory names. This avoids expanding arbitrary deletion authority in config. Existing broad directories are rejected by restworkspace rather than chmodded.
- **Runtime behavior:** Root validation occurs before listener bind; server API key and bounded manager precede workspace/executor initialization. Readiness is atomic and disabled before manager admission closes. HTTP shutdown precedes worker cancellation; the default bounded shutdown is 15 seconds. Workspace startup/hourly sweeps report only counts through optional safe logging.
- **Friction:** The runtime cannot be placed in package `restserver` because `restapi` already imports `restserver`; the composition was placed in `internal/restserver/runtime`. Initial focused compilation confirmed this import cycle, so package layout was changed before proceeding. An attempted `make help` is not applicable: the repository Makefile has no help target.
- **Deferred:** The Compose gate is deferred to a separate operator-reviewed workflow; this PR implements direct local-process server execution only. No PAT, push, PR/merge, or deployment path was added.
