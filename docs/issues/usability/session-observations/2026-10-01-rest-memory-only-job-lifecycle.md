# REST MVP: process-local jobs and history

The user changed the REST MVP persistence direction: accepted jobs, status, idempotency data, and history should remain in process memory rather than PostgreSQL. They explicitly accepted loss of those records on process crash/restart and directed graceful shutdown to stop accepting work, cancel active jobs, perform bounded cleanup, and exit. The user clarified that clients (potentially agents such as Hermes) submit task-job requests over HTTP; Factory Server owns scheduling and management of the coding harness. The server selects an approved command such as `pi`, `claude`, or `codex`; no caller-controlled executable or arguments. A bounded in-memory queue and worker concurrency are desired, with one isolated harness process/workspace per job rather than a shared session. The user requested a local Docker Compose deployment-testing file and said database configuration can be injected accordingly; with PostgreSQL deferred, Compose will need to reflect the current no-database scope rather than imply a database dependency.

The canonical REST contract and roadmap were updated to state this is a proposed, not implemented, single-process service; no durable acceptance or restart recovery is promised. External Git/PR side effects still require careful reconciliation before retry after state loss. Issue URLs are excluded; an optional positive issue number refers to the configured alias repository.

The server is currently expected to use the existing Factory workflow layer with a server-selected coding-harness process per job. Shared long-lived Pi/RPC sessions were clarified not to be the intent. Graceful-shutdown workspace cleanup is desired after controlled cancellation, but must not delete evidence if an external Git/PR outcome is uncertain. Compose is for local integration testing, not a sandbox claim.

Previous provisional PostgreSQL and `golang-migrate` foundation work was independently published by its Factory worker before PR creation failed because the auto-generated title exceeded GitHub's title limit. Its commit exists on branch `factory-job-rest-config-migration-mvp-007b0053-78c6-4b3c-9106-81f5e4573d29`; there is no PR. It is not part of this documentation change, and its PostgreSQL/config/migration design should not be treated as accepted for the revised MVP.
