# PR #206 Darwin CI diagnosis — 2026-10-09

## Verified observations

- PR #206 head `f7e1895b92eee9ceb8875b4ca118c91c842b5b04` had Ubuntu CI passing and macOS CI failing in `TestSQLiteServerRejectsPathReplacementWhileOwnerLive`: replacement-path open returned `B_OPENED` instead of the expected ownership conflict.
- The regression is specifically on the newly added path-keyed ownership lock. The test launches separate owner and competitor test processes but inherited ambient environment, leaving `os.UserCacheDir()` dependent on each process's effective `HOME`; on Darwin this resolves below `$HOME/Library/Caches`.
- macOS `flock(2)` supports exclusive nonblocking advisory locks. The lock conflict mechanism itself is used by the passing same-path ownership tests; no evidence indicated a required production lock change. I made the replacement test give both helper processes the same temporary `HOME` and clear `XDG_CACHE_HOME`, making the path-lock directory deterministic and shared across platforms.
- The focused replacement-path test passed. `make test`, `make vet`, and `make build` passed on this Linux host. `GOOS=darwin GOARCH=arm64 go test -c` for `internal/restjobs` passed; actual Darwin runtime behavior still requires macOS CI.
- This diagnosis is based on the test's implicit cache-root configuration and the observed process results; the macOS runner itself has not yet rerun the modified test.

## Friction

- The subprocess test depended on a per-user OS cache path without making the expected shared test scope explicit. Explicit temporary `HOME` setup makes that dependency visible, repeatable, and isolated from developer/CI machine state.
