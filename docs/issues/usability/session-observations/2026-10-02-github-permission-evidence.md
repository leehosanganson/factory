# GitHub App permission evidence audit

- **Type:** Research session observation for a REST MVP design gate; not a user-reported finding.
- **What worked:** Reading GitHub's endpoint-specific REST documentation confirmed that OAuth-style user tokens are among the supported fine-grained token types for reference creation and pull request create/get operations. The endpoint pages state Contents: write for reference creation, Pull requests: write for PR creation, and Pull requests: read for PR retrieval. GitHub's App authentication docs state user-token authority is limited by both the user's and App's permissions/resources. The App-installation authentication page documents installation-token use for HTTPS-based Git access.
- **Evidence limits:** The fetched Get an issue endpoint page did not expose its fine-grained permission section, so the required permission for reading an issue remains unverified here. GitHub's cited HTTPS Git instructions cover installation access tokens, not the delegated user access token planned for this design. Do not infer user-token git clone/push support from REST endpoint support.
- **Scope status:** Update only the credential-custody design's evidence summary and references; do not select a final App permission set or implement Git transport.
- **Friction:** The issues endpoint page fetched successfully but the permission subsection was not present in the extract. SearXNG search was unavailable because its configured internal service address was blocked by the web tool, so remaining claims are explicitly left unverified rather than inferred.
