# GitHub user and installation repository-access checks

- **Type:** Evidence-based REST MVP security-design clarification; not a user-reported finding.
- **Evidence:** GitHub's official REST docs describe `GET /user/installations/{installation_id}/repositories` as listing repositories the authenticated user has explicit read, write, or admin permission to access for an installation; its response includes those user permissions and supports GitHub App user access tokens with Metadata: read. Separately, `GET /installation/repositories` lists repositories an App installation can access; it supports installation access tokens and requires no additional permission. These are two distinct checks for the approved user/App access intersection, not interchangeable evidence. GitHub's `GET /repos/{owner}/{repo}/issues/{issue_number}` endpoint lists GitHub App user access tokens and Issues: read.
- **Scope status:** Clarified source-issue and target-repository authorization text in the REST API contract and credential-custody design, including links to both repository-list endpoints. No installation-selection behavior, provider implementation, OAuth behavior, or admission code was added; cross-installation support remains subject to implementation tests.
- **References:** [Get an issue](https://docs.github.com/en/rest/issues/issues#get-an-issue); [List repositories accessible to an app installation](https://docs.github.com/en/rest/apps/installations#list-repositories-accessible-to-the-app-installation); [List repositories accessible to a user access token](https://docs.github.com/en/rest/apps/installations#list-repositories-accessible-to-the-user-access-token).
- **Verification:** Checked the endpoint descriptions, token types, permissions, and repository-permission response wording on GitHub's official REST documentation. Local Markdown links and `git diff --check` are checked before publication.
