# REST uncertain-provider process E2E

- **Scope:** Added a separate process-level SQLite scenario for a fake provider that durably records one PR create, then waits until the configured job timeout simulates a lost response. The test checks the job becomes `failed` with no provider outcome, records durable failure evidence, and retains its workspace; after a clean server restart it remains failed and startup does not replay the provider write. An explicit same-identity fake-provider retry returns the existing PR identity without incrementing create count.
- **Evidence:** `go test ./internal/restserver/runtime -run '^TestRESTServerProcessRecoversUncertainProviderCreateWithoutDuplicate$' -count=10` passed.
- **Coverage boundary:** Existing provider unit tests still exercise GitHub HTTP-level ambiguous response reconciliation. The process test adds timeout and restart evidence missing from the earlier happy-path E2E. It does not invoke live GitHub, automatically resume a job, or persist the explicit reconciliation result into the durable job; that remains an operator recovery responsibility.
- **What worked/friction:** The current process helper can be restarted against the same SQLite path to prove retained state and no blind replay. On the first draft, the child failed before calling the fake provider because the test harness script contained literal backslash escapes; checking job history exposed the setup error. Using a real multiline shell script made the intended scenario run. A canceled provider context alone leaves the manager's terminal failure write under the same canceled context; using the real bounded job timeout instead reliably records `failed` before restart.
